I attempted to use a web based Vim tutorial to practice basic text editing for my systems programming class. My goal was to learn how to delete specific words without using the backspace key as this is a common requirement for efficient terminal work.

The Interaction
I opened the application and was presented with a block of code and a blinking cursor. I wanted to delete the word integer from a line of C++ code. My Mental Model which is the internal map of how I expect a system to work was based on standard editors like VS Code where I just click and type. I immediately began typing the letters d and w to trigger the delete word command.

The interface shows a standard text block but provides no immediate indication of which mode is active.

However nothing happened on the screen. I felt a high level of Cognitive Load because I had to stop and remember if I needed to be in a specific mode. Because the interface lacked Visibility of System Status I could not tell if I was in Normal mode or Insert mode. I tried pressing the keys again but the system provided no Feedback or visual reaction to my keystrokes. This made me feel like the application was frozen or broken when in reality I was simply in the wrong mode.

The design also failed to provide a clear Signifier which is a physical or visual cue that tells a user what actions are possible. There was no prompt or highlight to guide me toward the correct sequence. I eventually realized I needed to press the escape key first but the lack of an Affordance for beginners made the task much harder than it needed to be.

Reflection and Analysis
This experience was not Satisfying because I spent more time fighting the interface than learning the actual command. The interaction lacked Error Tolerance because typing the wrong key in the wrong mode led to a dead end with no suggestion on how to fix it. Efficiency was ruined because I had to look at a separate cheat sheet on another tab to understand why the editor was not responding to my inputs.

This diagram shows the complexity of the commands that a user must memorize without visual help.

Proposed Solution
A simple fix for this problem is to include a persistent mode indicator that changes color when the user switches between Normal and Insert modes. Additionally the system should detect when a user is typing commands that do not work in the current state and provide a small helpful tooltip. These changes would lower the barrier to entry and make the learning process feel much more Intuitive for students who are new to the command line environment.
