I used the "Arch Vim" web-based platform to practice my terminal skills for my computer science lab. My goal was to move through the first three levels to build muscle memory for navigation and mode switching.

The Interaction
I began with Level 1 which focuses on basic file navigation. My initial Mental Model was built on using arrow keys to move a cursor but the instructions required using the h j k and l keys. The layout provided a clear Mapping where each key corresponded to a specific direction. I noticed that the editor displayed a small label at the bottom right indicating I was in Normal mode. This provided excellent Visibility of System Status because I always knew the state of the editor before I tried to move.

The interface clearly lists the command mappings to help users transition away from using arrow keys.

In Level 2 I practiced the process of exiting the editor. For many beginners this is a point of high Cognitive Load because the command is not intuitive. However the application provided clear Signifiers by explaining how to open the console with the colon key. When I typed the quit command the system responded immediately which gave me the Feedback I needed to feel confident in my control over the environment.
<img width="1920" height="1200" alt="image (1)" src="https://github.com/user-attachments/assets/a94d42eb-6198-4203-b5e9-d5a7bf362b64" />

By Level 3 I was introduced to Insert mode. I had to press the i key to start typing text. The Affordance of the editor changed as soon as I entered the new mode allowing me to input the word VIM inside the brackets. When I successfully completed the task a large green bar appeared at the bottom of the screen with the text You passed. This was a very Satisfying conclusion to the session because it confirmed my progress with a high contrast visual cue.

The success message provides immediate positive reinforcement and confirms that the objective was met.

Reflection and Analysis: 
This experience was far more Intuitive than trying to learn Vim in a standard terminal. The design reduces the fear of making mistakes because the environment is isolated and provides constant guidance. The Consistency of the layout across all three levels helped me focus on the commands rather than trying to figure out how to use the website itself. I felt a sense of User Control and Freedom because I could reset the level at any time if I got confused.

Proposed Solution: 
To make the experience even better the developer could add a small animation or sound effect when the mode changes. A subtle shift in the background color of the editor would further improve the Visibility of System Status and help users distinguish between Normal and Insert modes without needing to look at the bottom of the screen. This would allow students to keep their eyes on the code and further increase their Efficiency during practice.
